# Проверки

## NavMesh и Vertex Alpha версии 1.3

`hython tests/navmesh_alpha.py` создаёт новую сцену тестового процесса и отдельную временную папку `rtc_navmesh_alpha_*`, выполняет 130 проверок и сохраняет checks.json/verification.hip. Проверяются нормализация NavMesh, старые sidecar, повторное использование материалов, живое обновление покраски, общие точки материалов, экспорт исходных атрибутов и native FBX roundtrip. Текущую HIP-сцену интерактивного Houdini этот отдельный процесс не меняет.

`hython tests/preview_render.py <output-folder>` создаёт OpenGL-изображение и HIP с тремя строками: обычный четырёхслойник, декаль, непрозрачный материал; столбцы Alpha 0 / 0.25 / 0.5 / 1. На тестовых мешах render flag намеренно направлен на предпросмотр, потому что OpenGL ROP обычно использует render-поток. В рабочих сценах render flag остаётся на исходном SOP. Этот тест требует графический OpenGL-контекст.

NavMesh в обновлённом Max не подтверждён локально: установленный аддон Max пока не читает `navmesh_type`. Проверки выше подтверждают формат и Houdini-часть; для назначения NavMesh в Max требуется обновлённый официальный аддон.

Скрипты требуют установленный Houdini 20.5 с Python 3.11 и лицензией FBX. Запускайте на отдельной копии репозитория. Они очищают сцену тестового процесса и записывают временные файлы.

## Политика материалов

Запустить `hython tests/material_policy.py`. Восемь проверок выбора исходного материала, сохранности исходных SOP и отказа при отсутствующей текстуре. Результат: `tests/policy_checks.json`; обмен: `tests/policy_exchange`. Рабочий пакет требует только `hou` и стандартную библиотеку.

## Три полных цикла Max → Houdini → Max

Нужен Max 2023 с исходным CarXBridge и RenderCore, NumPy из Houdini, а также локальная сцена `tests/Liza_Houdini_VERSION.max` (не распространяется в Git). Ожидания теста рассчитаны на здание Liza: 6 мешей и 18 имён материалов.

1. В новой копии репозитория создать `tests/sandbox`.
2. Для обоих тестовых процессов задать TEMP и TMP в абсолютный путь этой sandbox. Не использовать рабочую `%TEMP%/CarXBridge`.
3. Проверить, что INI тестового Max не указывает на рабочий обмен: использовать отдельный профиль и каталог sandbox/CarXBridge, GlobalScale=1.
4. Запустить `tests/max_cycles.py` через 3dsmaxbatch, затем `tests/houdini_cycles.py` через hython. Тесты согласуют три цикла через request/max_ready JSON.
5. Изучить `tests/reuse_checks.json`, проверить отсутствие ошибок процессов.

Старые request/max_ready JSON нельзя использовать для нового прогона: запускать в новой копии. Тест сохраняет `tests/cycles_VERSION.max` и `tests/repeated_exchange.hip`; исходная сцена остаётся отдельной.
