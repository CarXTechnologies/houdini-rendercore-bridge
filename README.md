# Houdini RenderCore Bridge

Двусторонний обмен статическими моделями и материалами RenderCore между Houdini 20.5 и 3ds Max. Версия **1.2.0**. Blender не требуется.

## Быстрый запуск

**Обязательная зависимость для 3ds Max:** установите аддон **CarXBridge** из [CarXTechnologies/3D-bridges](https://github.com/CarXTechnologies/3D-bridges) по инструкции этого репозитория. Он устанавливается отдельно от Houdini-пакета. Также в Max должен быть установлен RenderCore.

1. Скачать репозиторий через **Code → Download ZIP**, распаковать и запустить `Install.cmd`.
2. Перезапустить Houdini; включить **+ → Shelves → RTC RenderCore**.
3. Houdini → Max: **Send to Max**, затем прежняя **Get from Blender** в Max.
4. Max → Houdini: прежняя **Send to Blender**, затем **Get from Max** в Houdini.

Нужны Houdini 20.5 / Python 3.11 с поддержкой FBX, 3ds Max с RenderCore и действующим CarXBridge. Проверенная конфигурация: Houdini 20.5.278 и Max 2023.2.2. Max-скрипты, RenderCore, текстуры и пользовательские сцены в репозиторий не входят.

Подробности: [GUIDE.md](GUIDE.md), [тесты](tests/README.md), [история](CHANGELOG.md).

[Краткая инструкция со скриншотами (PDF)](docs/Houdini_RenderCore_Bridge_Quick_Guide_RU.pdf).

## Правило материалов

При **Get from Max** сначала ищется уже существующий RenderCore-материал по полю **Source material name**. Если найден — новые грани получают ссылку на этот узел. Его шейдер, текстуры, tiling, коллизия и остальные настройки не перезаписываются входящими данными. Если материал не найден — он создаётся, как раньше. Сравнение имени не зависит от регистра.

Имена узлов Houdini вроде `plaster_9`, `plaster_91`, `plaster_92` не считаются разными материалами, если их **Source material name** одинаков. Намеренно разные Source material name, например `Shared` и `Shared1`, остаются разными материалами.

Для сцен, в которых копии уже накопились, **Send to Max** также выбирает один существующий материал на имя: сначала узел с исходным именем без автоматического суффикса; если такого нет — по кратчайшему пути с устойчивым порядком. Экспортируемая копия геометрии переназначается на этот материал. Поэтому разные параметры старых копий больше не вызывают конфликт имён. Исходные SOP и их назначения при экспорте не меняются.

Старые узлы-копии автоматически не удаляются: в них могут оставаться ваши правки. Новые импортируемые партии получают уже существующий материал, а не новую копию. Если две версии материала должны сохранить разные настройки, дайте им разные **Source material name**. Для изменения существующего материала редактируйте его узел в Houdini; повторный импорт из Max его настройки не обновляет — это намеренное правило этой версии.

Повторное использование касается RenderCore-материалов мостика. Обычный Principled-материал без параметров RenderCore не превращается автоматически в RenderCore.

## Обновление

1. Запустить `Install.cmd` из распакованного архива. Предыдущий установленный пакет сохраняется в `.backup-дата`.
2. Перезапустить Houdini, чтобы выгрузить старые Python-модули.
3. Продолжить пользоваться той же полкой RTC RenderCore и кнопками Max **Send to Blender / Get from Blender**.

Коррекция осей и единиц версии 1.1 сохранена. Для ранее импортированных объектов Max с X=90° остаётся однократный Reset XForm до повторной передачи, поскольку штатный Max при замене сохраняет прежний transform. Полное описание ограничений и установки — в `GUIDE.md`; файлы отчётов предыдущей версии перечислены там как исторические и хранятся в архиве 1.1.0.

## Что проверено в 1.2

- Три реальных полных цикла Max → Houdini → Max на здании Liza, 6 мешей и 18 имён материалов. После первого импорта количество RenderCore-узлов Houdini остаётся 18; в последующих импортах создаётся 0, повторно используется 18.
- Локальные правки варианта шейдера и tiling в Houdini сохраняются при получении материала с тем же именем из Max.
- Смоделирована старая сцена с конфликтующим дублем и отсутствующей у него текстурой: экспорт использует исходный материал и завершается успешно, не удаляя дубли и не меняя исходные SOP.
- Ошибка отсутствующей текстуры у выбранного исходного материала по-прежнему останавливает экспорт, сохраняя предыдущие файлы обмена.
- Проверены фактические назначения граней, один материал на имя в исходящих JSON/FBX и неизменность Max-скриптов.

Max 2023 в этом наборе использует 25 экземпляров sub-material с 18 именами; это состояние не растёт в трёх циклах. Изменение самой Max-системы материалов не входит в пакет: его штатные скрипты сохранены побайтово. Исправление предотвращает накопление Houdini-копий и конфликт при их экспорте.

## Воспроизведение теста

Нужны Houdini 20.5 и Max 2023 с установленными RenderCore и исходным CarXBridge. Тестовые процессы должны работать с собственными TEMP/TMP в `tests/sandbox`, а не с рабочей папкой обмена. В отдельном Max batch запустить `tests/max_cycles.py`, затем в hython — `tests/houdini_cycles.py`. Они согласуют три цикла через служебные JSON в `tests`; запускать из новой распакованной копии, без старых `request_*.json` и `max_ready_*.json`. Самостоятельный тест политики — `tests/material_policy.py` через hython. Обычная работа установленного мостика дополнительных зависимостей не требует.
