# RenderCore Bridge 1.2.0 — Houdini 20.5 ↔ 3ds Max 2023

Двусторонний мостик для статических полигональных моделей и RenderCore-материалов. Скрипты Max не изменяются. Blender для работы не нужен.

## Установка и обновление

**Сначала установите аддон для 3ds Max:** [CarXBridge — CarXTechnologies/3D-bridges](https://github.com/CarXTechnologies/3D-bridges). Следуйте инструкции в этом репозитории. Аддон Max устанавливается отдельно и обязателен для обмена; Houdini-установщик его не устанавливает. В Max также требуется RenderCore.

Распаковать архив, запустить `Install.cmd`, перезапустить Houdini 20.5. В меню полок **+ → Shelves → RTC RenderCore** включить полку. Старый установленный пакет и JSON настроек автоматически сохраняются рядом с суффиксом `.backup-дата`. Для нестандартной папки настроек: `powershell -File Install.ps1 -PreferencesDirectory "D:/HoudiniPrefs"`.

## Из Max в Houdini

1. Выделить меши в Max и нажать существующую **Send to Blender**.
2. В Houdini нажать **Get from Max**.
3. Появится OBJ Subnet **From_Max** с редактируемыми сетями **FROM_MAX (Stash) → OUT**. В `/mat` создаются только отсутствующие материалы; при совпадении Source material name назначается существующий материал с сохранением его настроек. Настройки находятся во вкладке **RenderCore → 3ds Max**: вариант шейдера, текстуры, tiling слоёв, поверхность коллизии и отдельный **Enable collision**.

Импорт читает `TMP_MAX.fbx` и файлы `.mat`, которые выдаёт текущий Max-мостик. Геометрия, UV, нормали, Cd/Alpha и назначения материалов сохраняются в HIP; импортированная геометрия не зависит от временного FBX. Текстуры продолжают использовать исходные пути, в архив не упаковываются.

Каждый импорт создаёт отдельную партию **From_Max**, **From_Max1** и т. д. Предыдущая работа не заменяется. Для последующего экспорта выбрать нужную партию; одновременный экспорт старой и новой партии с одинаковыми именами объектов будет отклонён. Удалять или объединять старые партии можно после приёмки.

Имена Houdini автоматически очищает от недопустимых символов. Исходное имя Max хранится в `rc_export_name` у OBJ, имя материала — в **Source material name**. При восстановлении материалов учитываются исходные FBX-имена, в том числе когда Houdini переименовал повторяющийся `stone_3` в `stone_4`. Если разные исходные имена становятся неоднозначными после очистки, импорт останавливается с объяснением.

## Из Houdini в Max

Создать полигональную модель, подготовить UV и нормали. Через **New RC Material** создать материал, настроить его первую вкладку **RenderCore → 3ds Max**. Через **Assign RC Material** добавить Material SOP; для разных частей использовать группы примитивов в Material SOP. Уже существующий `shop_materialpath` тоже поддерживается.

Выделить Geometry OBJ, конечные SOP или OBJ Subnet и нажать **Send to Max**. После завершения отправки нажать прежнюю **Get from Blender** в Max. Повторная передача с теми же именами использует штатную замену объектов Max без дублей.

## Оси, масштаб и трансформации

Houdini: **Y-up**. Max: **Z-up**. В экспортируемой копии геометрии применяется `(x, y, z) → (x, −z, y)`. Трансформации OBJ сначала запекаются в эту копию. В FBX явно указаны метры, автоматическое создание FBX PreRotation и масштабного узла отключено. Исходные узлы Houdini не поворачиваются и не масштабируются.

Для импорта native FBX выполняет обратное преобразование Z-up → Y-up с учётом единиц файла. Затем трансформации запекаются в импортируемую геометрию, OBJ остаются с нулевыми rotation/translation и масштабом 1. Таким образом сохраняется мировое положение статических мешей, а дополнительного X=90° на объекте нет. Это запекание трансформаций: исходные локальные pivot и иерархия не восстанавливаются.

Проверка нулевого вращения и единичного масштаба Max выполнена в сцене с System Units = meters и штатным GlobalScale = 1. Для обоих направлений `[Import]`/`[Export] GlobalScale` Max должен быть 1. Штатный Max `Replace_Objects.py` копирует rotation/scale старого объекта при замене. Поэтому для объектов, уже принятых версией 1.0 с X=90°, **перед повторным импортом** однократно выполнить стандартный **Utilities → Reset XForm → Reset Selected**, сохранив резервную копию сцены. Это запечёт прежнюю трансформацию без поворота здания в мире. Затем отправить модель новой версией. Обычное ручное обнуление Rotation вместо Reset XForm повернёт старую геометрию — такой способ не использовать. Альтернатива для проверки — импортировать в чистую тестовую сцену.

## Ограничения

- Проверено на Houdini **20.5.278 / Python 3.11** и Max **2023.2.2** с установленным RenderCore и предоставленным CarXBridge. Houdini должен иметь лицензию с поддержкой FBX.
- Поддерживаются V2, Layered, MeshDecal, MeshDecalLayered и отдельный Collider-материал. Остальные материалы отклоняются. Если у Max не было файла `.mat` для использованного материала, импорт останавливается.
- Статические полигоны. Packed instances предварительно распаковать; curves/volumes преобразовать. Анимация, скиннинг, Entity/helpers, OBJ-иерархия и исходные pivot не входят в эту версию.
- Отрицательный OBJ-scale при экспорте отклоняется: отражение нужно выполнить в SOP и исправить winding. Ненулевые положительные transform, rotation и неравномерный scale запекаются.
- Collider требуется отдельным мешем: штатный Max-скрипт не создаёт `cxColliderMaterial` внутри Multi/Sub-Object.
- Штатный Max читает Tiling только у `RenderCoreLayeredMaterial`. Для других шейдеров изменять UV через SOP. Этот предел нельзя убрать только Houdini-стороной.
- UV1 и первый RGBA-канал проверены на здании. Дополнительные каналы требуют проверки на конкретном ассете.
- Это перенос параметров RenderCore, а не реализация RenderCore-рендерера в Houdini. Предпросмотр Principled ограничен первым слоем. Проблема тёмного аппаратного предпросмотра из версии 1.0 этой доработкой не объявляется исправленной. **Preview RC** меняет только настройки viewport (headlight, вклад Cd).
- Сохраняются ограничения текущего Max-мостика: уникальные имена, отсутствие суффиксов `.001` у объектов. Не передавать одновременно из разных приложений.

## Пути и резервные копии

Каталог FBX берётся из существующего Max `settings.ini`, секции `[Path] BRIDGE`. Файлы материалов и META штатный Max читает из `%TEMP%/CarXBridge` независимо от пользовательского пути FBX. Импорт читает папку `Materials`, экспорт пишет `MaterialsBlender`. INI и скрипты Max только читаются. Если найдено несколько активных профилей, задать `RTC_MAX_BRIDGE_INI` с путём нужного INI.

Перед публикацией исходящие файлы проверяются и предыдущая передача сохраняется в `%TEMP%/CarXBridge/HoudiniBackups/<id>`. Путь указан в `HoudiniLastExport.json`; подпапки `0`, `1`, `2` содержат предыдущие FBX, META и MaterialsBlender. Импорт не заменяет файлы обмена и не удаляет существующую сцену.

## Проверки и разработка

Сценарии воспроизведения и зависимости описаны в [tests/README.md](tests/README.md). Пользовательские сцены и исторические отчёты не включены в Git. Ранее выполненные интеграционные проверки не запускаются автоматически при клонировании.

Сборка переносимого ZIP: `python build_release.py`. Нужен Python 3.11; Houdini для самой сборки не требуется. В архив входят пакет, установщик, документация и исходники тестов, без моделей и сторонних Max-скриптов. Проверяются SHA256 и целостность ZIP.
